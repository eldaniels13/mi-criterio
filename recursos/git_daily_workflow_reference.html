Flujo del día — en este orden
git status → git pull --rebase → git diff → git add → git commit → git push
Orientación — siempre antes de todo
seguro
git status
Estado del repo: rama actual, archivos modificados, sin commitear, adelante/atrás del remoto.
seguro
git log --oneline -5
Últimos 5 commits en una línea. Ver quién hizo qué sin scroll infinito.
seguro
git log --oneline --graph --all
Árbol visual de todas las ramas. Esencial cuando tienes P1–P8.
seguro
git diff
Qué cambió línea por línea en archivos todavía no stageados.
seguro
git diff --staged
Qué está en el stage listo para commitear. Revisar siempre antes de git commit.
seguro
git remote -v
Confirmar que origin apunta a github.com (SSH, no HTTPS).
Sincronización con GitHub
seguro
git fetch origin
Descarga cambios del remoto sin aplicarlos. Ver antes de pull.
seguro
git pull origin main --rebase
Trae cambios y reescribe tus commits encima. Historial limpio, sin merge commits.
seguro
git push origin main
Subir commits locales a GitHub. Requiere que estés al día con el remoto.
config global
git config --global pull.rebase true
Hace que git pull use rebase por defecto en todos los repos. Set-and-forget.
Guardar cambios — el ciclo central
seguro
git add archivo.cs
Stagear un archivo específico. Más preciso que git add .
revisar antes
git add .
Stagear todo lo modificado. Usar solo después de git diff para saber qué incluyes.
seguro
git commit -m "tipo(scope): msg"
Guardar el stage con mensaje. feat / fix / docs / refactor / chore.
corrige el último
git commit --amend
Modificar el mensaje o agregar archivos al último commit. Solo si no has hecho push.
Pausar trabajo en progreso
Cuándo usarlo: quieres hacer pull o cambiar de rama pero tienes cambios sin commitear que no están listos.
seguro
git stash
Guarda cambios sin commitear en un cajón temporal. El directorio queda limpio.
seguro
git stash pop
Recupera los cambios del cajón y los vuelve a aplicar en el directorio.
seguro
git stash list
Ver todos los stashes guardados si tienes varios acumulados.
destructivo
git stash drop
Borra el stash más reciente permanentemente. No hay undo.
Ramas — trabajo por proyecto (P1–P8)
seguro
git branch
Lista todas las ramas locales. La rama activa tiene un asterisco.
seguro
git checkout -b P2-arch
Crea rama nueva y te cambia a ella en un solo comando.
seguro
git checkout main
Volver a main (o cualquier otra rama existente).
fusiona historial
git merge P2-arch
Integra la rama P2-arch en la rama donde estás. Correr desde main.
post-merge
git branch -d P2-arch
Borra la rama ya fusionada. Git bloquea esto si hay commits sin fusionar.
seguro
git show HEAD
Detalle completo del último commit: autor, fecha, diff incluido.
Deshacer — con cuidado
Regla de oro: antes del push, puedes reescribir historia libremente. Después del push, necesitas --force-with-lease y hay que saber lo que se hace.
seguro — solo quita del stage
git restore --staged archivo.cs
Saca un archivo del stage sin tocar el contenido del archivo.
borra cambios del archivo
git restore archivo.cs
Descarta cambios no stageados en un archivo. Los cambios se pierden.
solo pre-push
git reset HEAD~1
Deshace el último commit pero conserva los cambios como unstaged. Buen undo.
destructivo
git reset --hard HEAD~1
Deshace el último commit Y borra los cambios. No hay recuperación fácil.
en medio de rebase/merge
git rebase --abort  /  git merge --abort
Salida de emergencia: cancela el rebase o merge en progreso y vuelve al estado anterior como si nada.
Conflictos — los pasos cuando git se detiene
Git se detiene, te muestra qué archivo tiene conflicto, y espera. No hay urgencia.
paso 1
git status
Ver exactamente qué archivos están en conflicto ("both modified").
paso 2
nano archivo-en-conflicto
Abrir el archivo, editar hasta que quede como quieres, borrar los marcadores <<<<< ===== >>>>>.
paso 3
git add archivo-en-conflicto
Marcar el conflicto como resuelto. Git lo interpreta como "ya lo arreglé".
paso 4
git rebase --continue
Continuar el rebase desde donde se pausó. O git merge --continue si era un merge.
