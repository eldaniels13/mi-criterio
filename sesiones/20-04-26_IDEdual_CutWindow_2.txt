CONCEPTOS APRENDIDOS EN ESTA SESIÓN
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  · Code-OSS — el código fuente MIT de VS Code que Microsoft publica.
    VSCodium compila binarios directamente de ahí sin los componentes
    propietarios. VS Code (binario de microsoft.com) incluye piezas
    cerradas: C# Dev Kit, Remote-*, Live Share, client del marketplace.

  · Open VSX Registry — marketplace alternativo mantenido por Eclipse
    Foundation. Vendor-neutral. Usado por VSCodium, Theia, Eclipse Che,
    Gitpod, Coder. Los términos de uso del Microsoft Marketplace
    prohíben a editores no-Microsoft jalar extensiones de ahí — no es
    técnico, es legal.

  · Extensiones MS bloqueadas en Open VSX por licencia: ms-dotnettools.csharp,
    C# Dev Kit, ms-python.pylance, Remote-SSH, Remote-Containers, Live Share.
    Alternativas comunitarias: muhammad-sammy.csharp (OmniSharp + debugger
    MIT de Samsung), ms-pyright.pyright (motor abierto de Pylance).

  · FIM — Fill-in-the-Middle. Formato especial de prompt donde el modelo
    recibe contexto antes Y después del cursor. Los modelos "coder" pequeños
    (1.5B-3B) entrenados para FIM hacen autocomplete usable en CPU sin
    necesidad de 7B+. Separa autocomplete (pequeño, rápido) de chat
    (grande, inteligente).

  · Embeddings — vectores numéricos que representan significado semántico
    de texto/código. Continue usa embeddings para @codebase: cuando
    preguntas "dónde está la función de rotación", no hace grep textual,
    busca por similitud semántica. nomic-embed-text es el modelo para eso.

  · Continue.dev config — cambió de config.json (legacy) a config.yaml
    (schema v1) en 2025. La nueva sintaxis permite roles por modelo:
    chat, autocomplete, edit, apply, embed.

  · Licencia no-comercial JetBrains — disponible desde oct 2024.
    Activación gratuita con cuenta JetBrains, revalidación cada 30 días
    (envía email + fingerprint + versión, no código). Funciona offline
    entre revalidaciones.

  · Arquitectura Ollama — daemon HTTP en localhost:11434. Modelos cuantizados
    (GGUF) en ~/.ollama/models/. Carga a RAM on-demand. Inferencia en CPU
    (sin GPU aceleración práctica para Intel UHD). Verifica soberanía real:
    `nmcli radio wifi off && ollama run modelo "prompt"` → funciona.

  · Soberanía de datos — framework de 4 componentes:
    1. Código fuente auditable del editor
    2. Telemetría y dónde va
    3. Dónde corre la inferencia (local vs cloud)
    4. Lock-in del formato/vendor
    La soberanía pragmática prioriza #3 y reversibilidad sobre #1 absoluto.

  · Continue dev_data — ~/.continue/dev_data/ guarda localmente prompts
    y completions aceptados. No sube a ningún servidor (si Continue
    telemetry está off), pero queda en disco. Relevante para modelo
    de amenaza si laptop compartida o en reparación.

  · Proyectos .NET compatibilidad Linux:
    · net8.0 / netstandard2.0 class library → ✓ compila
    · net8.0 + xUnit/NUnit tests → ✓ compila
    · net48 (.NET Framework) → ✗ no compila
    · net8.0-windows + WPF/WinForms → ✗ requiere Windows Desktop Runtime
    · AutoCAD plugin (ObjectARX/Managed) → ✗ SDK Windows-only
    Rider marca con ícono tachado los proyectos que no cargan.

  · Separación Core vs Adapters — patrón de arquitectura limpia.
    El Core contiene lógica de dominio pura (algoritmos, modelos),
    sin dependencias de plataforma. Los adapters son las piezas que
    hablan con sistemas externos (AutoCAD, WPF, CLI, webapp, DB).
    Permite que el Core compile y se pruebe en cualquier lado, y que
    los adapters se cambien sin tocar lógica.
